Give it a script. It reads it back in your voice.

One command, myna studio, launches the whole pipeline as an application in your browser. This page is the five-minute tour: see the app, hear it, read how it works, and see where two adversarial reviews pushed back.

The application

Myna Studio: one command, whole pipeline

myna studio starts a loopback-only server and opens the app: pick or enroll a voice, paste a script, tune delivery, and Generate. Synthesis progress streams live — each chunk lands as the Apple GPU finishes it — then the take auto-plays with its speaker-similarity verdict and joins a replayable history. How it works

Zero-shot conditioning, not training

Myna never trains on your voice. It uses Chatterbox TTS (MIT-licensed, 0.5B parameters), which conditions on the first ~10 seconds of your reference clip and generates speech in that voice. Enrolment just assembles your best reference audio — instant, reversible, no GPU-hours. That's why the whole pipeline could be built and proven before the owner records a single word: it's speaker-agnostic by construction.

script→ chunk (sentence-aware)→ condition once→ generate (Apple GPU)→ stitch + pauses→ verify

Full architecture, the 10-engine selection tournament, latency tradeoffs, and every cited source: docs/design.md.

Run it

From clone to spoken script in three commands

# one-time setup
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e ".[dev]"
source .venv/bin/activate

# enroll the shipped stand-in voice, then launch the application
myna enroll standin demo/assets/arctic_000*.wav demo/assets/ref_a.wav
myna studio          # opens http://127.0.0.1:8787 — script in, voice out

# the same pipeline, scriptable
myna say --script your-script.txt --voice standin -o out.wav --verify

Setup, the application, CLI reference, and the recording kit: README.md · docs/recording-scripts.md. 51 offline tests pass in ~2 s.

Is it honest?

An adversarial review, and what it changed

Two red-team passes ran — one against the CLI/engine, a second against the Studio application — each told to refute every claim. Between them they found a genuine data-loss bug, two real security holes in the app, and several overstatements. Nothing is hidden; the fixes shipped in the same changeset.

  • Fixed · was critical (app): "loopback only" was oversold as security — any web page in the same browser could have driven the local server (cross-origin CSRF) or read it via DNS rebinding. A same-origin guard now rejects foreign Origin and non-loopback Host headers.
  • Fixed (app): enrolling an existing voice name silently overwrote it; the network endpoint now refuses (409) without an explicit overwrite. Upload size/count capped; job memory bounded.
  • Fixed · was critical (CLI): the recording kit said record with Voice Memos (.m4a), but enrolment rejected .m4a. Now decoded via an ffmpeg fallback, verified against a real AAC file.
  • Disclosed: the verifier shares a vendor and embedding family with the engine, so it's "separate", not "independent"; a different speaker still scores ~0.67–0.71 — and --verify measures who it sounds like, not what was said. Read the numbers against that floor; listen to your outputs.

Both rounds — every finding, verdict, and remediation status: docs/red-team.md. Every judgement call made without asking a human: docs/build-log.md.
